# 04 - 主Bot设计

## 1. 主Bot职责

主Bot是平台的入口，负责：
- 用户注册子Bot（提交Token）
- Bot主人管理自己的子Bot
- Bot主人发起广播
- Bot主人封禁/解封用户
- 平台管理员管理广告、查看统计、管控所有Bot

## 2. 命令总览

| 命令 | 权限 | 说明 |
|------|------|------|
| `/start` | 所有人 | 欢迎页 + 功能导航 |
| `/help` | 所有人 | 帮助信息 |
| `/register` | 所有人 | 注册新的子Bot |
| `/mybot` | Bot主人 | 管理自己的Bot列表 |
| `/broadcast` | Bot主人 | 向Bot用户群发消息 |
| `/block` | Bot主人 | 封禁/解封用户 |
| `/admin` | 平台管理员 | 平台管理面板 |
| `/ad` | 平台管理员 | 广告管理 |

## 5. /register 命令 - 注册子Bot

### 交互流程（完整步骤）

```
步骤1: 用户发送 /register（或点击"注册新Bot"按钮）

主Bot回复:
┌─────────────────────────────────────────┐
│ 请发送你的 Bot Token                     │
│                                         │
│ 你可以从 @BotFather 获取Token：           │
│ 1. 打开 @BotFather                      │
│ 2. 发送 /mybots                          │
│ 3. 选择你的Bot                           │
│ 4. 点击 "API Token"                      │
│ 5. 复制Token并发送给我                    │
│                                         │
│ Token格式: 123456:ABC-DEF1234ghIkl-zyx   │
│                                         │
│ [取消]                                   │
└─────────────────────────────────────────┘

此时主Bot进入等待Token输入的状态（FSM State: waiting_token）
```

```
步骤2: 用户发送Token文本

主Bot执行验证:
├─→ 2a. 格式校验：正则匹配 ^\d+:[A-Za-z0-9_-]+$
│       失败 → 回复"Token格式不正确，请重新发送"，保持等待状态
│
├─→ 2b. 重复检查：查询数据库是否已注册该Token
│       已存在 → 回复"该Bot已被注册"
│       如果是当前用户注册的 → 提示"这是你已注册的Bot @xxx"
│       如果是其他用户注册的 → 提示"该Bot已被其他用户注册"
│
├─→ 2c. 数量检查：查询该用户已注册的Bot数量
│       >= MAX_BOTS_PER_USER → 回复"你最多只能注册 {N} 个Bot"
│
├─→ 2d. API验证：调用 Bot(token).get_me()
│       失败 → 回复"Token无效，请检查后重新发送"
│       成功 → 获取 bot_info（id, username, first_name）
│
└─→ 2e. 验证全部通过

主Bot回复:
┌─────────────────────────────────────────┐
│ 检测到Bot信息：                           │
│                                         │
│ 名称: My Feedback Bot                    │
│ 用户名: @MyFeedbackBot                   │
│ ID: 7654321                              │
│                                         │
│ 确认将此Bot注册为双向机器人吗？             │
│                                         │
│ [确认注册]  [取消]                        │
└─────────────────────────────────────────┘
```

```
步骤3: 用户点击"确认注册"

主Bot执行:
├─→ 3a. 加密Token（Fernet加密）
├─→ 3b. 写入数据库（sub_bots表）
├─→ 3c. 调用 BotRegistry.add_bot(token) 启动子Bot
├─→ 3d. 启动成功

主Bot回复:
┌─────────────────────────────────────────┐
│ 注册成功!                                │
│                                         │
│ 你的Bot @MyFeedbackBot 已开始工作         │
│                                         │
│ 现在任何人给 @MyFeedbackBot 发消息，       │
│ 你都会在这里收到通知。                     │
│ 直接回复消息即可回复对方。                  │
│                                         │
│ [管理此Bot]  [返回主菜单]                 │
└─────────────────────────────────────────┘

如果启动失败:
┌─────────────────────────────────────────┐
│ 注册已保存，但Bot启动失败。               │
│ 错误: {error_message}                    │
│                                         │
│ Bot已标记为"错误"状态，你可以稍后          │
│ 在 /mybot 中重新启动。                    │
│                                         │
│ [我的Bot]  [返回主菜单]                   │
└─────────────────────────────────────────┘
```

### FSM 状态机

```
[idle] ──/register──→ [waiting_token] ──收到Token──→ [confirming] ──确认──→ [idle]
                           │                              │
                           └──取消──→ [idle]               └──取消──→ [idle]
```

## 7. /broadcast 命令 - 广播消息

  主Bot回复:
  ┌─────────────────────────────────────────┐
  │ 请选择要广播的Bot：                       │

  │ [@MyBot1 (156个用户)]                    │
  │ [@MyBot2 (42个用户)]                     │

## 8. /block 命令 - 封禁用户

### 交互流程

```
方式A: 直接命令
用户发送: /block 123456

主Bot执行:
├─→ 查询 user_id=123456 是否存在于用户的某个Bot中
│
├─→ 不存在: 回复 "未找到该用户"
│
├─→ 存在于1个Bot中: 直接封禁
│   回复: "已封禁用户 张三 (ID:123456) - @MyBot1"
│
└─→ 存在于多个Bot中:
    ┌─────────────────────────────────────────┐
    │ 用户 张三 (ID:123456) 存在于多个Bot中：   │
    │                                         │
    │ [封禁于 @MyBot1]                         │
    │ [封禁于 @MyBot2]                         │
    │ [全部封禁]                               │
    │ [取消]                                   │
    └─────────────────────────────────────────┘
```

```
方式B: 回复转发消息时使用
（Bot主人在子Bot中收到转发消息后，在主Bot中操作）

用户发送: /block（不带参数）

主Bot回复:
┌─────────────────────────────────────────┐
│ 请发送要封禁的用户ID                      │
│                                         │
│ 你可以在转发的消息头部找到用户ID           │
│ 格式: 纯数字，如 123456789               │
│                                         │
│ [取消]                                   │
└─────────────────────────────────────────┘
```

```
封禁后效果:
- 该用户发给子Bot的消息将不再转发给Bot主人
- 子Bot自动回复: "你已被限制使用此Bot"
- Bot主人可通过 /block 123456 再次执行来解封

解封确认:
┌─────────────────────────────────────────┐
│ 用户 张三 (ID:123456) 当前状态: 已封禁    │
│                                         │
│ [解除封禁]  [取消]                        │
└─────────────────────────────────────────┘
```

## 11. 回调数据命名规范

所有 callback_data 使用以下格式：`{模块}_{动作}:{参数}`

| 前缀 | 模块 | 示例 |
|------|------|------|
| `reg_` | 注册流程 | `reg_confirm`, `reg_cancel` |
| `bot_` | Bot管理 | `bot_manage:123`, `bot_stop:123` |
| `bc_` | 广播 | `bc_select:123`, `bc_confirm`, `bc_cancel` |
| `blk_` | 封禁 | `blk_user:123:456`, `blk_unblock:123:456` |
| `adm_` | 管理员 | `adm_bots`, `adm_stats`, `adm_system` |
| `ad_` | 广告 | `ad_list`, `ad_add`, `ad_edit:1` |
| `page_` | 分页 | `page_users:123:2`, `page_bots:3` |
| `nav_` | 导航 | `nav_home`, `nav_back` |

## 12. FSM 状态总览

| 状态组 | 状态 | 触发 | 等待输入 |
|--------|------|------|----------|
| Register | `waiting_token` | /register | Bot Token 文本 |
| Register | `confirming_register` | Token验证通过 | 确认/取消按钮 |
| Welcome | `waiting_welcome` | 点击"设置欢迎语" | 欢迎语文本 |
| Broadcast | `selecting_bot` | /broadcast（多Bot） | 选择Bot按钮 |
| Broadcast | `waiting_content` | 选择Bot后 | 广播内容（任意消息类型） |
| Broadcast | `confirming_broadcast` | 收到内容 | 确认/取消按钮 |
| Block | `waiting_user_id` | /block（无参数） | 用户ID数字 |
| Ad | `waiting_ad_text` | 添加广告 | 广告文本 |
| Ad | `waiting_ad_url` | 输入文本后 | 广告链接（可跳过） |
