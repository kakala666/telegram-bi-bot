## 2. 分层职责

| 层 | 位置 | 职责 | 规则 |
|----|------|------|------|
| **Handler 层** | `master_bot/handlers/`, `sub_bot/handlers/` | 接收 Telegram Update，解析参数，调用 Service | 禁止直接操作数据库；禁止包含业务逻辑 |
| **Service 层** | `services/` | 业务逻辑编排（转发、广播、广告注入、Token验证） | 通过 Repository 访问数据；不直接构造 SQL |
| **Repository 层** | `repositories/` | 数据 CRUD 抽象 | 只做数据读写；不含业务判断 |
| **Model 层** | `database/models.py` | SQLAlchemy ORM 模型定义 | 纯数据结构定义 |
| **Config 层** | `config.py` | 环境变量加载、全局配置 | 只读，启动时加载一次 |

## 3. 两个 Dispatcher 的关系

系统运行 **两个独立的 Dispatcher**：

| Dispatcher | 管理的 Bot | Router | 用途 |
|------------|-----------|--------|------|
| `master_dp` | 1 个（主Bot） | `master_router` | 处理平台管理命令 |
| `sub_dp` | N 个（所有子Bot） | `sub_router` | 处理双向消息转发 |

两个 Dispatcher 在同一个 asyncio 事件循环中并发运行：

```python
async def main():
    # 初始化数据库
    await init_db()

    # 启动主Bot
    master_bot = Bot(token=config.MASTER_BOT_TOKEN)
    master_task = asyncio.create_task(
        master_dp.start_polling(master_bot)
    )

    # 恢复所有活跃子Bot
    await bot_registry.recover_all()

    # 等待直到收到停止信号
    await master_task
```

## 5. 启动流程

```
launcher.py 执行
    │
    ├─→ 1. 加载 config.py（读取 .env）
    │
    ├─→ 2. 初始化数据库引擎（engine.py）
    │       └─→ 创建所有表（如果不存在）
    │
    ├─→ 3. 创建 Master Bot 实例
    │       └─→ Bot(token=MASTER_BOT_TOKEN)
    │
    ├─→ 4. 创建 BotRegistry 实例
    │       └─→ 内部创建 sub_dp（子Bot的Dispatcher）
    │
    ├─→ 5. 调用 registry.recover_all()
    │       ├─→ 查询数据库所有 status='active' 的 SubBot
    │       ├─→ 逐个解密 Token
    │       ├─→ 逐个创建 Bot 实例并验证
    │       ├─→ 验证失败的标记为 status='error'
    │       └─→ 验证成功的加入 _bots 字典
    │
    ├─→ 6. 启动 sub_dp.start_polling(*所有子Bot)
    │       └─→ 作为 asyncio.Task 后台运行
    │
    ├─→ 7. 启动 master_dp.start_polling(master_bot)
    │       └─→ 阻塞在此，直到收到 SIGINT/SIGTERM
    │
    └─→ 8. 收到停止信号
            ├─→ 停止 master_dp
            ├─→ 停止 sub_dp（关闭所有子Bot session）
            └─→ 关闭数据库连接
```
